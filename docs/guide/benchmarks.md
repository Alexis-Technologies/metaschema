# Benchmarks

Every number on this page comes from scripts in the repository, recorded in
[`bench/results/`](https://github.com/Alexis-Technologies/metaschema/tree/main/bench/results) and
turned into these charts and tables by `pnpm bench:report`. They were measured on one machine,
named under each chart. Read them as relative guidance: the order and the orders of magnitude
carry over to other hardware, the exact figures do not. How the core gets its speed is on the
[Performance](/guide/performance) page.

### How to read it

The libraries do different work for one call, so read the chart as a price list, not a ranking.

- **A verdict and a result are different prices.** TypeBox's `Compile`, Ajv and ArkType's
  `allows` return a boolean from generated code and allocate nothing on a valid value: that is
  the floor of a few nanoseconds a call, and the reason they lead the loose modes.
  metaschema's `check` returns a `ValidationResult` with a context behind it (two allocations a
  call); Zod, Valibot and Effect build a result object and, in the parse modes, a copy of the
  value without its unknown keys.
- **The strict modes cost every code generator the same scan.** Rejecting unknown keys means
  counting the keys of the value, which is where the generated validators come closest to one
  another, and where metaschema's JIT sits among them.
- **Generated code or not.** metaschema's JIT, TypeBox's `Compile`, Ajv, ArkType and Zod's
  object fast path generate code with `new Function`. Where that is forbidden (a strict Content
  Security Policy, Cloudflare Workers) metaschema keeps its closures, the second metaschema
  row: still ahead of every interpreter in the set (Valibot, Effect Schema, TypeBox's
  `Value.Check`, Joi, Superstruct, Yup and Metarhia's metaschema). Zod and ArkType fall back to
  interpreters of their own there, which this run does not measure.
- **Every issue is where the work differs most.** Asked for every issue of an invalid value with
  its path, a library that throws, formats messages or builds an issue tree per call pays for
  it; metaschema records issues as data and renders each message once, after the walk. Ajv's
  generated code builds its error objects inline and is the one faster here, with a JSON
  Pointer string for a path; Ajv's own security guide advises against `allErrors` in
  production.
- **Building a schema is the other side of code generation.** A library that generates code
  pays for it once per schema: Ajv builds about two thousand schemas a second, ArkType, TypeBox's
  `Compile` and metaschema's JIT a few tens of thousands, metaschema's closures two hundred
  thousand, and Valibot and Superstruct, whose schemas are plain objects of functions, two
  million. It matters at start-up and for a program that builds schemas per request.
- **Metarhia's metaschema has no loose mode** (its `check` always rejects unknown keys), so it
  is missing from those charts. **TypeBox 1.x's `Value.Check`** is an interpreter of JSON
  Schema and much slower than its `Compile`, and slower than 0.34's was. **Yup** runs with
  `strict: true` and **Joi** with `convert: false`, so that neither casts; Joi also needs
  `unsafe()` on the number fields to accept `Number.MAX_VALUE`.

### Method

- Every (library, scenario) pair runs in a **fresh process**, so no library's JIT feedback or
  heap state leaks into the next one.
- Before anything is timed, each adapter must give the scenario's **verdicts**: the valid value
  accepted, the value with unknown keys accepted or rejected as the mode says, a value with a
  wrong field rejected, the four issues of the invalid value at their four paths, a built
  schema that accepts the valid value and rejects the invalid one. A mismatch aborts the run:
  a check that fails at once is fast and measures nothing.
- The measured function is called through **one megamorphic call site**, the same for every
  library, so no library's check is inlined into the measuring loop; that is how a program
  calls a validator. Calls are timed in chunks, so reading the clock never dominates a call of
  a few nanoseconds.
- After a one-second warmup, calls are timed in **five one-second samples** and the median is
  reported; the tooltip shows the spread.
- The suite's own published numbers come from a different harness (benchmark.js, direct calls
  in one process), so they are not comparable with these one to one, only the order is.

Valibot and Superstruct are small because a program imports only the functions it uses (Zod's
own `zod/mini` builds the same schema in about 5 KB). metaschema's core is one entry: the whole
language, with unions, references, the format rule, `parse` and the async methods, comes with
the first import, and the JIT adds 4.2 KB to it. Metarhia's metaschema is smaller and validates
less: no unions, no `parse`, no async validators, issues as strings.

## Reproducing the numbers

```bash
pnpm bench:compare                      # libraries and cold start → bench/results/compare.json
pnpm size:compare --json                # bundle sizes → bench/results/size.json
git archive v3.1.0 | tar -x -C ../metaschema-3.1.0
node bench/releases.js --src ../metaschema-3.1.0   # one release → bench/results/releases.json
node bench/releases.js --src node_modules/metaschema
node bench/releases.js                  # the current tree, both backends
pnpm bench --save                       # metaschema's own scenarios → bench/baseline.json
pnpm bench:report                       # the charts (docs/public/benchmarks) and the tables here and in the README
```

`pnpm bench:compare --only metaschema,zod --scenarios nested,invalid` measures a subset and
merges it into the existing results; `--samples`, `--sample-ms` and `--warmup-ms` change the
method, `--cold-runs 0` skips the cold start.
