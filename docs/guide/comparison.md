# Compared with alternatives

metaschema sits where four kinds of tools meet: the TypeScript-first validators (zod, Valibot,
ArkType, Effect Schema and their kin), the JSON Schema validators and ahead-of-time compilers
(Ajv, TypeBox, typia), the interface definition languages built for schema evolution (Avro,
Protocol Buffers, and Metarhia's metaschema, which this project was forked from) and the schemas
of an object-document mapper (Mongoose). The table below compares it with twenty of them, every
feature in one table, rather than a few convenient libraries in a few convenient rows.

## What the table shows

- **One definition, the whole lifecycle.** Effect Schema comes closest in breadth (codecs, JSON
  Schema both ways, samples, streams, an LLM profile), and Mongoose and the IDLs have parts of
  a domain model; only metaschema is a validator with inferred types whose schemas are also
  entities with references (an id or the record), indexes and relations, assembled into a
  model with a snapshot, a `diff` of two versions and a compatibility class for the change.
- **Every issue as data is not the norm.** Seven of the twenty-one report a code, the path as
  keys and the parameters of each issue; the rest give a JSON Pointer, a dotted string or a
  message. Eight stop at the first issue unless told otherwise (protobuf.js always does), and
  only metaschema takes a cap per call (`maxErrors`); TypeBox has one for the whole process.
- **An async validator can let bad data through.** In ArkType, myzod, Valita and TypeBox a
  validator that returns a promise passes, because a promise is truthy; Joi's `custom()`,
  Valibot's synchronous `safeParse` of an async schema and class-validator's `validateSync`
  do the same. metaschema throws `ERR_ASYNC_VALIDATOR` from the synchronous methods.
- **Cyclic or very deep input overflows the stack in twelve of them.** metaschema tracks cycles
  where a record is embedded and stops at `maxDepth`; Joi and myzod turn the overflow into an
  issue, and protobuf.js has a depth limit.
- **Code generation is a trade.** VineJS and avsc cannot run where `new Function` is forbidden
  (a strict Content Security Policy, Cloudflare Workers), Ajv needs code generated at build
  time there, and Zod, ArkType and TypeBox generate code by default and fall back to an
  interpreter. metaschema generates nothing unless `compile()` is asked, and falls back the
  same way.
- **Some are no longer moving.** Superstruct (last release 2024-07, with a maintained fork by
  MetaMask), io-ts (2024-12) and myzod (2025-02).

## How the table was made

- **From the code, not the README.** Each library was installed at its latest version from npm
  (October 2026) and every cell decided by reading its source, and where the behaviour was not
  obvious from reading (the default of error collection, unknown keys, a cyclic value, whether
  a format exists), by running a script against it. A README claim the code does not back is
  not counted, and the footnotes say where the two disagree.
- **Built in or official.** A feature counts as ✅ when the package has it or an official
  package of the same project does (named in the cell); a third-party package is ⚠️ and named.
  A ❌ means it is not built in: most of them can be written by hand on top.
- **The same questions for everyone.** The rows were fixed before any column was filled, and a
  row that does not apply to a kind of tool is marked — rather than ❌.
- **metaschema's gaps are shown as such.** It has no coercion of input types, no partial of a
  schema, and the JIT needs `new Function` (it falls back to the closures without it).

The speed of the libraries that can be benchmarked side by side is on the
[Benchmarks](/guide/benchmarks) page, with the method; this page is about what each one does.

## Where each one fits

- **metaschema**: one plain-object definition for validation, parsing, TypeScript types, JSON
  Schema and a domain model that evolves; any runtime, with or without `eval`.
- **Zod**: the largest ecosystem and the default choice of many frameworks; codecs, JSON
  Schema both ways, a whole-schema compiler.
- **Valibot**: the smallest bundles, built from functions a bundler can drop.
- **ArkType**: definitions in TypeScript's own syntax, set-theoretic types and their
  relations, generated code.
- **Effect Schema**: programs built on Effect; the broadest feature set of the TypeScript-first
  libraries, much of it marked unstable.
- **Yup, Joi, VineJS**: form and request validation with casting and a wide rule set; Joi in
  hapi, VineJS in AdonisJS.
- **class-validator**: DTO classes with decorators, as in NestJS.
- **Superstruct, io-ts, Runtypes, myzod, Valita**: small composable validators; io-ts for
  fp-ts code, Runtypes for exact optional keys, Valita small with Standard Schema.
- **Ajv**: a JSON Schema document is the contract, in every draft.
- **TypeBox**: JSON Schema objects with static types and a fast compiled check.
- **typia**: TypeScript types are the source of truth, compiled ahead of time.
- **avsc, protobuf.js**: binary encoding and schema evolution shared with other languages.
- **Mongoose**: documents stored in MongoDB, cast, validated and persisted in one step.
- **Metarhia metaschema**: the original, inside the Metarhia stack; see
  [Migrating from metarhia](/guide/migrating-from-metarhia).
